# Автотесты UnicoPlay Web - Playwright + TypeScript

[![Tests](https://github.com/vidadi87/Playwright-TypeScript/actions/workflows/tests.yml/badge.svg)](https://github.com/vidadi87/Playwright-TypeScript/actions/workflows/tests.yml)

Регрессионный набор UI-автотестов для онлайн-кинотеатра [Unico Play](https://unicoplay.com): гость, вход по почте с OTP-кодом, авторизованный пользователь без подписки во взрослом и детском профилях.

Проект Unico Play закрыт, тестовых стендов нет, поэтому тесты идут на боевом сайте. Это учебный проект для портфолио: от чек-листа и тест-кейсов до кода.

## Регионы: Казахстан и зарубежный пользователь

Сайт определяет страну по IP. За пределами Казахстана он показывает урезанный каталог, а функции (вход, профили, плеер, поиск, «Буду смотреть», оценки, меню аккаунта) те же:

| | Казахстан | За рубежом |
| --- | --- | --- |
| Язык при первом входе | баннер выбора языка, по умолчанию казахский | баннера нет, сразу английский (`/en`) |
| Меню разделов | Фильмы, Сериалы, Детям, ТВ, Кино на ТВ, Спорт, Новинки | Фильмы, Сериалы, Детям |
| Линейки главной и каталог | полный | другой набор линеек, часть фильмов и мультфильмов недоступна |

Набор тестов один на обе страны:

- **Тестовые данные** выбраны из продуктов, доступных и в Казахстане, и за рубежом: «Рэкетир. Новые времена», «Черная икра», «Алтын адам», «Грузовичок Лёва».
- **Переменная `REGION`**: `kz` (по умолчанию, локальный запуск) или `intl` (GitHub Actions — серверы в США). От неё зависят ожидаемые разделы меню (`test-data/region.ts`).
- **Проверки только для Казахстана** помечены тегом `@kz-only` и при `REGION=intl` не запускаются: смена языка через баннер (1.1.1). Разделы ТВ, Кино на ТВ, Спорт, Новинки в 1.6.1 и 3.3.2.1 проверяются только для Казахстана.
- **Итого:** из Казахстана — 43 теста, из-за рубежа — 42.
- **Ограничение за рубежом:** на главной детского профиля линейка «Детский сериал» недоступна (сервер отвечает 500). Для `REGION=intl` тест 4.1.2 помечен как ожидаемое падение (`test.fail`): если линейку откроют, тест об этом сообщит.

## Стек

- [Playwright Test](https://playwright.dev) + TypeScript, браузер - Google Chrome (в Chromium из комплекта Playwright нет кодеков H.264/AAC для видео)
- Page Object + фикстуры Playwright
- ESLint (`typescript-eslint` с проверкой типов, `eslint-plugin-playwright`) + Prettier
- [imapflow](https://imapflow.com) + [mailparser](https://nodemailer.com/extras/mailparser/) - чтение OTP-кода из тестового Gmail по IMAP
- Чек-лист и тест-кейсы - Notion

## Структура

```
tests/
  auth.setup.ts              вход один раз за прогон, сессия сохраняется (storageState)
  1-guest.spec.ts            [1] гость
  2-auth.spec.ts             [2] вход по почте
  3-authorized.spec.ts       [3] трейлеры, переключение профилей
  3-account-changes.spec.ts  [3] язык и аватар профиля (меняют данные на сервере)
  4-navigation.spec.ts       [4] навигация, поиск, меню аккаунта
  4-account-changes.spec.ts  [4] «Буду смотреть», оценка (меняют данные на сервере)
pages/        Page Object страниц: главная, карточка продукта, вход, поиск, раздел, профили
components/   общие части страниц: шапка, плеер, меню аккаунта, окно языка
fixtures/     фикстуры: страницы, главная на русском, сбор ошибок страницы
test-data/    продукты, разделы меню, профили, регион, данные формы входа, известный «шум» ошибок
utils/        mailbox.ts - OTP-код из письма; profileApi.ts - настройки профилей с сервера
```

Проекты в `playwright.config.ts` идут в таком порядке:

```
setup ──► chromium               гость и вход по почте
      └─► chromium-authorized ──► chromium-account-changes (1 воркер)
```

## Запуск

Нужны Node.js 20.12+ и установленный Google Chrome.

```bash
npm ci
cp .env.example .env   # заполнить адрес тестового Gmail и пароль приложения Google
npm test               # все тесты
npm run test:guest     # только гость (без почты)
npm run report         # HTML-отчёт последнего прогона
npm run typecheck      # проверка типов
npm run lint           # ESLint: в том числе пропущенный await
npm run format         # Prettier: оформление кода
```

- Без `.env` выполняются только тесты гостя и проверки формы входа (2.3), остальные пропускаются.
- Аккаунт Unico Play должен быть заранее зарегистрирован на тестовый Gmail, в ящике включён IMAP.
- Один прогон отправляет одно письмо с кодом. При частых запросах кода сайт показывает капчу: тест падает с понятным сообщением, капчу нужно ввести вручную.

## CI (GitHub Actions)

Workflow [`tests.yml`](.github/workflows/tests.yml):

- **При каждом пуше и pull request** — typecheck, ESLint, Prettier. На сайт не ходят.
- **Тесты — только ручной запуск** (Actions → Tests → Run workflow), потому что идут на боевом сайте. Серверы GitHub находятся в США, поэтому тесты идут с `REGION=intl` — как у зарубежного пользователя (см. «Регионы»). Набор на выбор:
  - `guest` — тесты гостя, без почты;
  - `all` — весь набор; нужны секреты репозитория `TEST_EMAIL` и `GMAIL_APP_PASSWORD`, прогон отправляет 2 письма с кодом.
- HTML-отчёт прикладывается к прогону как артефакт. Скриншоты, видео и трейсы в CI выключены: на них виден адрес тестовой почты, а артефакты публичного репозитория доступны всем.

## Ключевые решения

- **Селекторы без `data-testid`.** На сайте их нет, а классы - CSS-модули с хэшем (`StartPlayerProgress_root__bar___FEuE`). Поэтому ищем по ролям и текстам, а по классам - по началу имени: `[class*="StartPlayerProgress_root"]`.
- **Видео.** Реклама перед серией пропускается, только если она есть: кнопка «Пропустить» появляется через 5–8 секунд. Воспроизведение проверяется по росту времени, перемотка - кликом по середине полосы прогресса.
- **Вход один раз за прогон.** `auth.setup.ts` входит по коду из письма и сохраняет сессию. Пока она действует, письма не отправляются.
- **Одно письмо на группу входа.** Неверный код (2.2) и верный (2.1) вводятся на одном экране: повторный запрос кода вызывает капчу.
- **Тесты, меняющие аккаунт.** Язык, аватар, «Буду смотреть» и оценки хранятся на сервере, поэтому эти тесты идут отдельным проектом по одному, после остальных, и возвращают исходное состояние.
- **Регионы.** Один набор тестов на Казахстан и зарубежного пользователя: общие тестовые данные, переменная `REGION` и тег `@kz-only` для проверок, которые есть только в Казахстане.
- **Проверка по данным сервера.** Сохранённый язык профиля интерфейс показывает ненадёжно, поэтому он читается из API сайта (`utils/profileApi.ts`).
- **Ошибки страницы.** Во всех тестах собираются JS-ошибки и ответы сервера с кодом ≥ 400. Известный «шум», который не является дефектом, вынесен в исключения с объяснением (`test-data/known-errors.ts`).
- **Секреты.** Адрес тестовой почты и пароль приложения - только в `.env`, который не попадает в git.
